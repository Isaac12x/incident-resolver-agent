# Releasing Incident Harness

The curl installer resolves a versioned wheel from the GitHub release API. The asset
is built from the tagged commit, so an installation does not need Git or a checkout.
Keep the version in `pyproject.toml` and the release tag in sync (for example, `0.2.0`
and `v0.2.0`).

## Build and verify

Run these commands from a clean checkout of the release commit:

```bash
uv lock --check
uv run ruff check .
uv run pytest
uv build
uv run --with dist/incident_harness-0.2.0-py3-none-any.whl incident-agent --help
```

The wheel filename generated by `uv build` contains the normalized project name
(`incident_harness`). Upload that versioned wheel, the sdist, and a `SHA256SUMS` file.
The installer selects the first `.whl` asset unless `INCIDENT_HARNESS_RELEASE_ASSET`
selects an exact asset name.

## Publish

Create the tag and GitHub release from the reviewed commit, then upload:

```bash
git tag -a v0.2.0 -m 'Release v0.2.0'
git push origin v0.2.0
gh release create v0.2.0 \
  dist/incident_harness-0.2.0-py3-none-any.whl \
  dist/incident_harness-0.2.0.tar.gz \
  --title v0.2.0 --generate-notes
shasum -a 256 dist/incident_harness-0.2.0-py3-none-any.whl | \
  sed 's#  dist/#  #' > /tmp/SHA256SUMS
shasum -a 256 dist/incident_harness-0.2.0.tar.gz | \
  sed 's#  dist/#  #' >> /tmp/SHA256SUMS
shasum -a 256 install.sh >> /tmp/SHA256SUMS
gh release upload v0.2.0 install.sh /tmp/SHA256SUMS
```

Verify the release asset before announcing the release:

```bash
curl -fI https://github.com/Isaac12x/incident-resolver-agent/releases/latest/download/incident_harness-0.2.0-py3-none-any.whl
```

## Installer behavior

```bash
curl -fsSL https://github.com/Isaac12x/incident-resolver-agent/releases/latest/download/install.sh | sh
```

The default resolves and installs the latest release's versioned wheel. Set
`INCIDENT_HARNESS_VERSION=v0.2.0` to pin a tag, or set
`INCIDENT_HARNESS_REPOSITORY=owner/repository` to use a fork that publishes a wheel.
`INCIDENT_HARNESS_RELEASE_ASSET` selects an exact asset name. For development
or source based installs, `INCIDENT_HARNESS_SOURCE` takes precedence and can be a Git
URL, local path, or wheel URL.

`incident-agent update` follows the source retained by uv. Set the version, repository,
asset, or source environment variables when changing release tracks; the installer
then force-installs the newly resolved wheel. Managed helper tools are upgraded only
after the main package succeeds.

## Isolated installation smoke test

Use a temporary uv tool directory to avoid changing the operator's installation:

```bash
tool_dir=$(mktemp -d)
bin_dir=$(mktemp -d)
UV_TOOL_DIR="$tool_dir" UV_TOOL_BIN_DIR="$bin_dir" uv tool install \
  --from https://github.com/Isaac12x/incident-resolver-agent/releases/latest/download/incident_harness-0.2.0-py3-none-any.whl \
  incident-harness
"$bin_dir/incident-agent" --help
rm -rf "$tool_dir"
rm -rf "$bin_dir"
```

Do not put API keys, GitHub tokens, or other credentials in release assets, installer
arguments, or release notes. The installer only selects a package source and delegates
dependency resolution to `uv`.
